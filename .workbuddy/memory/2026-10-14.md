# 2026-10-14

## 目标
用 Tauri 开发「B站视频解析工具」桌面端：输入 B 站链接 → 解析 → 导出 .mp4。

## 技术选型与关键结论

- 技术栈：**Tauri v2 + React 18 + TypeScript + Vite 6**，Rust 后端用 `reqwest`(rustls-tls) + `tokio`。
- **B 站播放地址有两条路**（实测结论，务必记住）：
  - `x/player/playurl?fnval=4048` → DASH，音视频**分离**（.m4s），画质上限高（登录后 4K），
    但必须用 ffmpeg `-c copy` 合并才能得到 mp4。
  - `x/player/playurl?fnval=1` → `durl` 单文件 mp4，**无需 ffmpeg**，但清晰度低
    （未登录 720P 封顶，实测 `accept_quality=[64,16]`）。
  - 因此做成「高清模式 / 兼容模式」双模式，高清为默认。
- **接口不需要 WBI 签名**：`x/web-interface/view` 与 `x/player/playurl` 直接可用。
- **必需请求头**：`User-Agent`(桌面 Chrome) + `Referer: https://www.bilibili.com`。
  实测**不带 Referer 下载 CDN 返回 403**；带 `https://www.bilibili.com` 即可（无需完整视频页 URL）。
- **CDN 支持 Range**：`Range: bytes=0-0` 返回 206 + `Content-Range: bytes 0-0/TOTAL`，可据此探测大小。
- **`data.quality` 字段不可信**（`fnval=4048&qn=127` 时报 64 但实际流只有 32）。
  画质列表要**从 `dash.video` 的 id 集合**推导。
- 未登录时 DASH 最高只有 480P(id=32)；填 `SESSDATA` 才能解锁 1080P/4K。
- 编码 codecid：7=AVC(H.264)、12=HEVC、13=AV1。默认选 AVC 兼容性最好。

## ffmpeg 分发的坑（重要）

- GitHub release 直连在本机**极慢**（77MB 下 10 分钟超时）；gyan.dev 完全不通。
- **最佳源：npmmirror 上的 `@ffmpeg-installer/win32-x64` tgz**，实测 **6.75 MB/s**：
  `https://registry.npmmirror.com/@ffmpeg-installer/win32-x64/-/win32-x64-4.1.0.tgz`
  包结构 `package/ffmpeg.exe`（64MB，ffmpeg 4.1，支持 AV1/HEVC/AAC/FLAC）。
  Rust 侧用 `flate2` + `tar` 解压（不需要 `zip` crate）。
- 备用源：`https://ghfast.top/<github原始地址>` 加速代理可用（实测 ~150KB/s）。

## Windows 平台踩坑

- **`std::os::windows::fs::FileExt` 没有 `write_at`**，只有 `seek_write`（且会移动本句柄的文件指针）。
  所以分片并发下载必须**每个分片任务各开一个文件句柄**，否则文件指针竞争写坏数据。
- **`tokio::process::CommandExt` 不可用**（报 private trait）。
  正解：先用 `std::process::Command` 组装（可调 `creation_flags(0x08000000)` 隐藏控制台），
  再 `tokio::process::Command::from(std_cmd)` 转成异步执行。
- Tauri `tauri-build` 在 `frontendDist` 目录不存在时会**直接报错**，cargo check 前需先建 `dist/`。
- tsconfig 用 `references` 指向 `tsconfig.node.json` 且后者 `noEmit: true` 会报 TS6310。直接去掉 references。

## 修复：「打开所在文件夹」错开成桌面目录

**现象**：下载完成后点「打开所在文件夹」，资源管理器打开的是**桌面**，不是视频所在目录。

**根因（Windows 命令行转义）**：
原来写法是 `format!("/select,\"{}\"", path)`，参数里**自己带了双引号**。
Rust 在 Windows 上按 VC++ 规则转义 argv，会把内层 `"` 转成 `\"`：
`explorer "/select,\"C:\...\x.mp4\""`
但 **explorer.exe 不遵循这套规则**，它自己解析原始命令行，遇到解析失败就退回
打开「默认目录」（表现为桌面）。同类坑还有：路径含空格时的外层引号。

**正解**：
1. 首选 Tauri 官方 opener 插件的 `tauri_plugin_opener::reveal_item_in_dir(path)`，
   Windows 下走原生 `SHOpenFolderAndSelectItems`（正确选中文件），
   失败时内部还有 `ShellExecuteExW` 兜底 —— 完全不碰命令行转义。
2. 退化方案 `tauri_plugin_opener::open_path(dir, None::<&str>)` 打开目录。
3. 最后兜底才用 `explorer`，且**参数里绝对不能自己加引号**：
   `format!("/select,{}", path)`，交给系统按自己的规则加。
4. `play_file` 也一并换成 `open_path`（原来用 `cmd /C start` 同样脆）。

**通用结论**：凡是要传给 `explorer.exe` / `cmd` 的 Windows 参数，
不要在参数内部手写双引号；能用原生 Shell API 就别用命令行。
这两个 free function 不依赖插件注册，但 `run()` 里仍注册了 opener 插件保持一致。

**注意**：`cargo run`（即 `tauri dev`）会全程持有 `target/debug/.cargo-lock`，
此时再跑 `cargo check` 会报 "拒绝访问 (os error 5)"。
可先 `tasklist | grep rustc` 确认是否还在编译；release 与 debug 的锁是分开的。

## 新增：下载时去除 B 站水印

**结论：可行，且已端到端验证成功。**

- 水印是**烧进像素**的半透明浅色叠加层，无法无损去除；用 ffmpeg 的 `delogo` 滤镜做邻域插值。
  delogo 必须**重新编码视频**（音频仍可 `-c:a copy`），用
  `-c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p`。
- **自动检测算法**（`src-tauri/src/watermark.rs`）：水印位置固定、视频内容在动，
  所以「在 ≥75% 采样帧里都是浅色低饱和（min>165 且 max−min<46）」的像素聚成的紧凑区块就是水印。
- **两个必须的判据**（第一版漏了，导致误判）：
  1. **只搜索画面上部 42%**。B 站水印固定在顶部；画面下部常有字幕/台标等同样静止的元素，
     第一版把左下角的字幕块（534 像素）当成了水印，把真正的水印（左上，138 像素）漏掉。
  2. **密度必须在 4%~45%**。文字/图形水印是镂空的（实测 13.5%），
     实心亮块密度 >50%，直接排除。
- 抽帧用 **rawvideo rgb24**（`-f rawvideo -pix_fmt rgb24 -`）而不是 PNG，
  这样 Rust 侧直接读字节做统计，不需要引入图像解码库。
- 检测用「下载前 18MB 前缀」而不是整段视频；前缀抓取必须**多线路 + 多轮重试**，
  因为 B 站 CDN 会偶发 503（实测遇到过）。
- 视觉框选：`detect_watermark` 顺便用 `-frames:v 1 -f image2pipe -c:v png -` 抓一帧
  缩到 900px 宽返回 data url，前端用百分比定位的 div 做拖拽/缩放，坐标按 src/disp 比例换算。
- **水印区域必须随分辨率重新定位**：前端用 `bvid-cid-qualityId-codecid` 做签名，
  签名变了就重新检测。
- 重编码进度：给 ffmpeg 加 `-progress pipe:1 -nostats`，解析 `out_time_us=` 换算百分比，
  通过 `ProgressState::set_percent_progress` 驱动原有进度条（total 记 1000）。
  注意 stderr 要**单独 spawn 任务读完**，否则管道写满会死锁。

**验证方式**（可复现）：
```bash
# 1. 带 --wm 跑自检（自动检测 + 去水印）
src-tauri/target/debug/bili-video-extractor.exe --selftest --wm "<B站链接>" ".tools/e2e/wm_out"
# 2. 用脚本对输出视频再检测一次水印位置
python scripts/detect_watermark.py ".tools/e2e/wm_out/xxx.mp4"
```
实测：原视频左上角持续浅色像素 **266 个** → 去水印后 **0 个**，且 ffmpeg 完整解码无报错。
（去水印产物 15.9MB，比原 9.7MB 大，属重编码正常现象。用户也能在下载时选择关闭。）
